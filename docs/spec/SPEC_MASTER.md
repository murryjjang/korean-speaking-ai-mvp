# AI 한국어 말하기 훈련·평가 MVP 상세 시방서 - 확장 최종본

문서 버전: 3.0 확장판
용도: 검토용 PDF/DOCX, Claude Code 작업용 MD, 외주 인계 초안

## 0. 문서 구성
- 1. 문서 사용법과 프로젝트 정의: 본 문서는 AI 한국어 말하기 훈련·평가 MVP를 Claude Code로 구현하기 위한 검토용·개발용·외주 인계용 통합 시방서이다. 사람이 읽는 PDF/DOCX와 Claude Code가 읽는 MD를 함께 제공하는 것을 전제로 한다.
- 2. MVP 범위와 제외 범위: 이번 MVP는 교재 디지털화 기능을 제외하고 말하기 평가, 말하기 대회 준비, 상황별 미션 대화, 교수자 채점, 대시보드를 우선 구현한다.
- 3. 사용자 역할과 권한: 학습자, 교수자, 관리자 역할을 명확히 분리하고 페이지·권한·데이터 접근 범위를 다르게 설계한다.
- 4. 전체 정보구조와 라우팅: Next.js App Router를 기준으로 학생, 교수자, 관리자, 공통 컴포넌트, API Route 영역을 분리한다.
- 5. 콘텐츠 유연화 설계: 말하기 평가 유형, 문항, 문제 세트, 루브릭, 상황 미션, 페르소나, 피드백 템플릿은 코드가 아니라 JSON 또는 DB 구조로 관리한다.
- 6. 말하기 평가 모듈: 오픽형을 초기 예시로 사용하되 유형은 고정하지 않는다. 진단평가, 연습평가, 사후평가 세트를 자유롭게 구성할 수 있게 한다.
- 7. 말하기 대회 준비 모듈: 초안 작성, AI 1차 교정, 학습자 재수정, 교수자 최종 교정, TTS 섀도잉, 발표 녹음, 평가를 하나의 루프로 구현한다.
- 8. 상황별 미션 대화 모듈: 식당, 병원, 교통, 관공서 등 상황에서 AI 페르소나와 대화하며 정해진 턴 안에 미션을 달성하는 구조를 구현한다.
- 9. 교수자 페이지 상세 시방: 교수자 페이지는 본 시스템의 핵심이다. 학생별, 반별, 모국어/어권별, 콘텐츠별, 기간별, 위험도별 필터와 AI 결과를 보며 채점하는 3단 레이아웃을 제공한다.
- 10. 관리자 대시보드 상세 시방: 개인별, 반별, 어권별, 콘텐츠별, 오류유형별, AI-교수자 차이 분석을 제공하고, 보충지도 추천과 보고서 export를 지원한다.
- 11. UI/UX 디자인 시스템: Pretendard 또는 Noto Sans CJK KR 기반의 전문적이고 차분한 교육기관형 인터페이스를 구현한다. 모든 페이지는 공통 디자인 토큰과 UI 컴포넌트를 사용한다.
- 12. Provider/Adapter 구조: STT, TTS, 발음평가, LLM 평가 API는 provider 인터페이스 뒤에 숨긴다. mock, ETRI, Azure, OpenAI, Claude 등으로 교체 가능해야 한다.
- 13. Supabase 데이터 구조: MVP 초기에는 mock data로 시작하지만, DB 연결을 대비해 테이블, 필드, 관계, 버전, provider 메타데이터를 명확히 설계한다.
- 14. 보안·개인정보·환경변수: .env.local, secret key, service role key, 음성 파일, 학습자 개인정보를 안전하게 관리한다.
- 15. 개발 단계와 Claude Code 운영: Claude Code는 Phase 단위로만 작업한다. 코드 전체 재작성 금지, 변경 전 계획 설명, 작업 후 테스트 방법 제시를 원칙으로 한다.
- 16. 테스트와 완료 기준: mock data 기준 전체 플로우가 동작하고, 교수자 페이지와 대시보드가 실제 시범운영에 필요한 정보를 보여주는지 검증한다.
- 17. 배포·운영·외주 인계: GitHub, Vercel, Supabase, 문서, 작업 로그, DB schema, 테스트 시나리오를 정리하여 외주 개발과 고도화의 기반 자료로 사용한다.
- 18. 부록: Claude Code 프롬프트: 초기 분석, Phase별 구현, 오류 수정, UI 개선, 리팩토링 제한 등 Claude Code에 그대로 붙여 넣을 프롬프트를 제공한다.

## 19. 상세 요구사항 카드
### R-001. [콘텐츠/구조] 콘텐츠와 코드 로직 분리
**목적:** 문제 유형·문항·루브릭·미션을 나중에 바꾸더라도 UI와 핵심 로직이 무너지지 않게 한다.

**기능 요구:**
- 관련 데이터는 src/content 또는 Supabase 테이블에서 관리한다.
- 컴포넌트는 ID와 메타데이터를 읽어 렌더링한다.
- 새 항목 추가 시 코드 수정이 최소화되어야 한다.

**완료 기준:**
- JSON 데이터만 수정해도 화면에 반영된다.
- 기존 문항/세트/루브릭을 삭제하지 않고 비활성화할 수 있다.
- Claude Code가 하드코딩 항목을 만들지 않는다.

**Claude Code 프롬프트:**
```text
현재 구조를 유지하고 콘텐츠 데이터 구조를 분리하라. 문제 유형, 세트, 루브릭, 미션, 페르소나는 코드에 하드코딩하지 말고 JSON/DB 구조로 관리하라.
```
