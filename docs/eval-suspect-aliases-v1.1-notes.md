# Eval — Suspect Alias Inventory & v1.1 LLM Prompt Design Notes

작성: 2026-05-12 / 컨텍스트: Q3 채점 버그 수정(v1.0 단계 1·2) 후속 메모. **이 문서는 보고용이며 코드 수정 없음.** v1.1 작업 시 참조.

관련 코드:
- `src/content/questions.json` — 공식 문항(q1~q4 × beginner/intermediate/advanced)의 `requiredElements` / `requiredElementAliases`
- `src/providers/llm-eval/index.ts` — `detectRequiredElements()`(키워드 substring 매칭 + v1.0에서 추가된 부정어 게이트), `getMockDetail()`(mock 채점), `elementKeywords` 정적 테이블(레거시 q-001~q-008 + alias 미제공 시 fallback)

매칭 메커니즘 요약: `transcript.toLowerCase().includes(alias.toLowerCase())` per alias, 요소별 하나라도 걸리면 `found`. v1.0 단계 2에서 매칭 위치 ±7글자 내 부정어(`안 ` / `않` / `못 ` / `아니` / `없`)가 있으면 해당 hit 무시. 즉 **여전히 단순 substring 매칭이라 (a) 짧은 일반 단어, (b) 더 긴 단어의 부분문자열, (c) 목적어가 다른 동사구가 오탐될 수 있음.**

## 1. q3 (qt-listening-resp) — v1.0 단계 1·2 적용 후 남은 의심 항목

대부분 정리됨. 남은 잔여 리스크:

| 레벨 | 요소 | 잔여 의심 alias | 오탐 예시 transcript | 권장 방향 |
|---|---|---|---|---|
| beginner | 오전 10시에 시작한다고 말함 | `"10시"` | "수업이 **10시간** 걸려요" / "오전에 했는데 **10시**쯤 끝났는지 모르겠어요"(시작 아님) | 시각 단위는 `"10시에"`·`"10시쯤"`·`"오전 10시"` 처럼 조사/맥락 포함 패턴 우선. 또는 `\d+시간` 제외 가드. |
| beginner | 2층 203호에서 한다고 말함 | `"2층"` | "**12층**에 있어요" / "옷을 **2층** 옷장에"(수업 장소 아님) | `"203호"`·`"이백삼호"`가 강신호. `"2층"`은 보조로만(이미 그러함). 큰 위험 아님. |
| intermediate | 수요일에서 금요일 오후 1시로 변경됐다고 말함 | `"1시"`, `"한 시"` | "**한 시간** 동안 발표해요" → `"한 시"` 매칭 / "**11시**"·"**21시**" → `"1시"` 매칭 | `"한 시"` 제거(거의 항상 `한 시간`의 일부). `"1시"`→`"1시에"`/`"오후 1시"`. |
| intermediate | 발표 자료를 목요일 오후 6시까지 이메일로 제출 | `"6시"` | "**16시**"·"**26시**"·"**6시간**" | `"6시"`→`"6시까지"`/`"여섯 시까지"` 또는 `\d+시간` 제외. |
| intermediate | 일정 변경의 핵심을 정확히 설명함 | `"바뀌었"` | 요소② "장소가 바뀌었어요"로도 매칭 — 요소 간 중복(이 요소가 "정확히 설명함" 메타라 큰 문제 아님) | 메타 요소는 다른 요소들의 found 개수로 파생 점수 매기는 게 더 정확. v1.1에서 재설계 고려. |
| advanced | 시간과 장소 제약이 줄어든다는 장점 언급 | `"제약"` | "**제약**이 많아서 불편해요"(단점 진술인데 장점 요소에 매칭. "많아"는 부정어 아니라 게이트 통과) | `"제약"` 단독 대신 `"제약이 줄"`·`"제약이 적"`·`"제약 없"` 등 방향성 포함, 또는 `"줄어들"`만 신뢰. |
| advanced | 온라인 자료 반복 복습 가능 장점 | `"반복"` | "**반복**되는 시험이 힘들어요"(off-topic) | `"반복 복습"`·`"반복해서 볼"` 등 결합 패턴 우선. |
| advanced | 자기 관리 능력 부족 시 효과 저하 단점 | `"단점"` | "**단점**은 통신비가 든다는 거예요"(다른 단점) — 다만 "단점 언급" 요소라 어느 정도 허용 가능 | 허용 범위. 정확도 필요 시 `"단점은 자기"`·`"단점은 스스로"` 결합. |

## 2. q1 / q2 / q4 + 레거시 elementKeywords — substring 오탐 의심 alias

### 2-1. q1 (qt-reading) — **구조적 약점**

q1 요소는 "문장을 끝까지 읽음", "자연스럽게 끊어 읽음" 등 *읽기 방식*에 대한 것이라 텍스트 키워드로는 원천적으로 검증 불가. 현재는 지문 본문 단어를 프록시로 쓰는데 그 단어들이 너무 흔함.

| 레벨 | 요소 | 의심 alias | 오탐 예시 | 권장 방향 |
|---|---|---|---|---|
| beginner-q1 | 문장 단위로 자연스럽게 끊어 읽음 | `"합니다"` | 거의 모든 격식체 문장이 `합니다`로 끝남 → 사실상 항상 매칭 | 삭제. 끊어읽기는 키워드로 못 잼. |
| beginner-q1 | 주요 정보 누락 없이 읽음 | `"집"`, `"수업"`, `"한국어"` | "**집**에 가요" / "**수업** 들어요" / "**한국어** 공부해요" — 무관 발화도 매칭 | 지문 고유 다어절 구절("병원에 갑니다", "한국어 수업이 끝나면")로 교체 + 매칭 비율 임계 상향. |
| beginner-q1 | 문장을 끝까지 읽음 | `"일찍"`, `"집에서"` | "**일찍** 일어났어요" / "**집에서** 쉬어요" | 위와 동일. |
| beginner-q1 | 기본 발음과 억양이 이해 가능함 | `"학교"`, `"병원"`, `"약국"` | "**학교**에 다녀요" | 위와 동일. 또는 이 요소 삭제(발음은 Azure 점수가 담당). |
| intermediate-q1 | 일요일/공휴일 미운영 내용을 낭독 | `"않습니다"` | 무수한 부정 문장이 `않습니다`로 끝남 | 삭제 또는 `"운영하지 않습니다"` 전체 구절로. |
| intermediate-q1 | 평일/토요일 운영 시간을 정확히 낭독 | `"오전"`, `"오후"`, `"9시"`,`"8시"`,`"10시"`,`"5시"` | "**오후**에 만나요" / "**5시간** 잤어요" / "**15시**" | 지문 고유 시간 쌍("오전 9시부터", "오후 5시까지")으로. |
| advanced-q1 | 의미 단위로 자연스럽게 끊어 읽음 | `"있습니다"`, `"됩니다"` | 거의 모든 문장 | 삭제. |
| advanced-q1 | 설명문의 논리 흐름이 드러나게 읽음 | `"교육"`, `"특히"`, `"능력"` | "**특히** 어려워요" / "**능력**을 키워요" | 지문 고유 구절로. |

→ **권장(q1 전반):** qt-reading 문항은 `required_elements_found`/`missing_elements` UI 자체를 노출하지 않거나(이미 q1 점수는 Azure 발음평가가 주도), alias를 "지문에서만 등장하는 4어절 이상 고유 구절"로 좁히고 found 비율 ≥ 0.75를 요구. v1.1 LLM 전환 시엔 LLM에게 "낭독 누락/발음 관점만 평가, 어휘·내용 확장 권하지 말 것"을 명시(이미 SYSTEM_PROMPT rule 8에 있음 — 유지).

### 2-2. q2 (qt-material-desc)

| 레벨 | 요소 | 의심 alias | 오탐 예시 | 권장 방향 |
|---|---|---|---|---|
| beginner-q2 | 손님이 음료를 주문하는 상황 설명 | `"사람"`, `"여자"` | "**사람**이 많아요" / "**여자**가 있어요" — 그림을 안 봐도 매칭 | `"손님이 주문"`·`"여자 손님"` 등 결합. `"사람"` 단독 제거. |
| beginner-q2 | 점원이 주문을 받는다고 설명 | `"받고"`, `"받습니다"`, `"받는"` | "선물을 **받고**" / "돈을 **받습니다**" | `"주문을 받"`·`"점원이 받"` 결합. 동사 단독 제거. |
| beginner-q2 | 배경 요소 언급 | `"배경"`, `"벽"`, `"메뉴"` | "**배경**이 밝아요"(메타 발화) / "**메뉴**가 다양해요" | `"메뉴판"`·`"계산대"`·`"시계"` 같은 구체 사물만. `"배경"`·`"벽"` 제거. |
| intermediate-q2 | 선호도 차이 이유 추측 | `"생각"`, `"때문"`, `"직접"`, `"선생님"` | "제 **생각**에는…"(거의 모든 의견 발화) / "친구를 **직접** 만나요" | 이유 요소는 `"때문에"` + 명사("선생님과 직접 이야기") 결합, 또는 LLM에 위임. `"생각"` 단독은 치명적. |
| intermediate-q2 | 온라인 30%라고 말함 | `"삼십"` | "**삼십** 분" / "**삼십** 명" | `"30%"`·`"30퍼센트"`·`"삼십 퍼센트"`만. `"삼십"` 단독 제거. |
| intermediate-q2 | 전체 결과 정리 | `"보입니다"` | "사람이 **보입니다**" | `"정리하면"`·`"전반적으로"`·`"결론적으로"`만. |
| advanced-q2 | 전체적 증가 추세 / 향후 전망 | `"계속"` (양쪽 요소에 중복) | "**계속** 공부했어요" — 무관 발화도 매칭, 게다가 두 요소 동시 매칭 | `"계속 증가"`·`"꾸준히 늘"` 결합. `"계속"` 단독 제거. |
| advanced-q2 | 특정 구간 큰 증가 | `"특히"`, `"크게"`, `"사이"` | "**특히** 좋아요" / "친구 **사이**" | `"2025년에서 2026년"`·`"증가 폭이"` 같은 구체 구간 표현. |
| advanced-q2 | 등록 인원 증가 | `"2024"`,`"2025"`,`"2026"`,`"등록"`,`"인원"` | 임의 연도 언급 / "**등록**금" / "**인원**이 부족" | `"120명"`·`"180명"`·`"260명"` 숫자쌍이 강신호. 연도 단독은 보조. |

### 2-3. q4 (qt-dialogue-mission)

| 레벨 | 요소 | 의심 alias | 오탐 예시 | 권장 방향 |
|---|---|---|---|---|
| **intermediate-q4** | 답변 듣고 정보 확인/정리 | **`"네"`** ← 파일 전체에서 가장 위험 | "**네** 시쯤요" / "보이**네**요" / "어머**니네** 집" / 의미상 "네"가 아니어도 음절 '네'만 있으면 매칭 | 즉시 제거 권장. `"알겠습니다"`·`"확인했습니다"`·`"그렇군요"` 등 다어절만. |
| intermediate-q4 | (전 요소 공통) | `"언제"`, `"가능"`, `"어떻게"`, `"선생님"`, `"수업이"` | "**언제** 와요?"(무관 질문) / "그게 **가능**해요?" | 미션형은 의도 단위 평가가 본질 → v1.1 LLM 위임이 정답. 임시로는 `"수업 시간이 언제"`·`"받을 수 있"` 같은 의도 구절 결합. |
| beginner-q4 | 포장/매장 이용 여부 | `"여기서"` | "**여기서** 기다릴게요"(주문과 무관) | `"여기서 마실"`·`"여기서 먹"`·`"매장에서"` 결합. `"여기서"` 단독 제거. |
| beginner-q4 | 수량을 말함 | `"1개"`, `"2개"` | "**1개**월" / "**2개** 국어" | `"1개"`→`"한 개"`·`"1잔"` 우선, 또는 `\d개월?` 가드. 위험 낮음. |
| advanced-q4 | 실무 협의 별도 회의 제안 | `"다시"` | "**다시** 말씀드릴게요"(메타) / "**다시** 만나요"(다른 맥락) | `"별도 회의"`·`"따로 잡"`·`"실무 협의"` 결합. `"다시"` 단독 제거. |
| advanced-q4 | 발표 주제 의견/제안 | `"AI"` | (영문 혼입 시) "ag**ai**n", "m**ai**n", "s**ai**d" 등 `ai` 부분문자열 | 한국어 전사면 위험 낮지만, 안전하게 `"에이아이"`·`"인공지능"`·`"AI 활용"` 등으로. |
| advanced-q4 | 일정 조정 가능 여부 확인 | `"가능"`, `"확인"`, `"언제"`, `"시간이"` | "그거 **가능**해요?" / "**확인**해 주세요"(무관) | 의도 구절 결합 또는 LLM 위임. |

### 2-4. 레거시 정적 테이블 `elementKeywords` (index.ts) — q-001~q-008 및 alias 미제공 fallback

공식 시연 세트(q1~q4)는 모두 `requiredElementAliases`를 제공하므로 이 테이블을 안 타지만, **alias 누락 시 fallback 경로**이고 레거시 문항에선 그대로 쓰임. 단음절 alias 다수:

| 키 | 위험 alias | 비고 |
|---|---|---|
| `'수업 시작 시간 언급'` | `'시'` | 단음절 — "시간/시작/시험/도시/회사/의사…" 거의 전부 매칭. **최악**. |
| `'수업 장소 언급'` | `'호'`, `'층'` | `'호'` — "호텔/전화/기호/번호…" 매칭. |
| `'비교 표현 사용'` | `'더'`, `'덜'` | `'더'` — "더워요/어디서/했더라…" 매칭. |
| `'인물의 행동 묘사 (최소 1가지)'` | `'하는'`, `'사람들'` | `'하는'` — 모든 관형절("공부하는/좋아하는…"). |
| `'각 그림 상황 또는 분위기 묘사'` | `'사람들'`, `'도시'` | 흔함. |

→ **권장:** 1글자·2글자 흔한 alias는 전면 제거. fallback 테이블 자체를 폐기하고 alias 없는 요소는 그냥 `missing` 처리(과채점 방지)하는 편이 안전. 레거시 q-001~q-008이 운영에서 안 쓰이면 테이블 통째 삭제 검토.

### 2-5. 공통 권장 방향 (요약)

1. **단음절/2음절 흔한 단어 alias 전면 금지** (`시`,`호`,`층`,`더`,`네`,`사람`,`여자`,`생각`,`계속`,`특히`,`다시`,`언제`,`가능`,`삼십`,`합니다`,`있습니다`,`됩니다`,`않습니다` 등).
2. **동사 어간 단독 → 목적어/대상 포함 구절로** (`받고`→`주문을 받`, `가져`(이미 제거됨)→`교재를 가져`).
3. **숫자+시각/단위는 조사·맥락 포함** (`10시`→`10시에`/`오전 10시`, `\d시간`/`\d개월` 제외 가드 추가).
4. **방향성 있는 요소는 방향 포함** (장점 요소의 `제약`→`제약이 줄`; 단점 요소의 `효과`→`효과가 떨어`).
5. **부정어 게이트(v1.0)는 유지하되 보강 후보**: 무공백 부정("안가져가요"), 후행 부정 어미("~지 못해요"의 `못해`), 이중부정 등은 현재 못 잡음. 윈도우를 ±10으로 늘리거나 정규식 `안\s?[가-힣]`·`[가-힣]\s?(못|않)[가-힣]` 추가 고려. 단, 너무 공격적이면 정상 매칭 손실 — v1.1에서 케이스 수집 후 조정.
6. **q1(낭독)·q4(대화미션)은 키워드 매칭이 본질적으로 부적합** → v1.1 LLM 전환 시 우선 대상. 그 전까지 mock에선 found 비율 임계만 보수적으로.

## 3. v1.1 — `LLM_EVAL_PROVIDER=openai` 전환 시 prompt 설계 권장사항

현재 `callOpenAI()`(index.ts)는 LLM에 `[질문 프롬프트]` / `[필수 포함 요소]`(라벨만) / `[학생 답변 전사문]` / `[발음 평가 참고]`만 전달. **`listeningScriptForTeacherOnly`(듣기 원문)·`modelAnswer`(정답 예시)는 전달 안 함.** q3(듣고 답하기)는 학습자가 들은 내용을 재현하는 문항이라, 평가자가 "정답에 무엇이 들어있어야 하는지"를 모르면 정확 채점 불가.

### 3-1. reference answer 노출 방식

- **q3(듣고 답하기) 한정으로 듣기 스크립트/모범답안을 LLM에 전달.** 단, "학습자에게 보여주지 말 것"·"corrected_answer에 그대로 복사하지 말 것" 명시. 예:
  ```
  [채점 기준 — 학습자 비공개] 학습자가 들은 안내 방송 내용:
  "{listeningScriptForTeacherOnly}"
  [필수 포함 요소] {requiredElements}
  ```
  그리고 SYSTEM_PROMPT에 "위 스크립트는 정답 판정용 내부 자료다. corrected_answer와 learner_feedback에 스크립트 문장을 그대로 인용하지 말고, 학습자 발화가 스크립트의 핵심 정보를 얼마나 정확히/완전히 재현했는지로 task_completion_score를 매겨라"를 추가.
- q1(낭독)은 지문이 학습자에게 이미 보였으므로 referenceText를 그대로 줘도 무방하나, "낭독 누락·발음·끊어읽기 관점만" 가이드 유지(현 rule 8).
- q2/q4는 modelAnswer를 "예시"로만 주고 "유일 정답 아님, 다른 타당한 표현도 인정" 명시.
- 공통: `corrected_answer`는 절대 transcript·script를 복붙하지 말고 독립 작성(현 rule 1 유지).

### 3-2. 부정문·목적어 구별을 위한 평가 기준 명문화

SYSTEM_PROMPT의 scoring rules에 추가 권장:
- "required_elements_found에는 **학습자가 해당 정보를 긍정적으로·정확히 진술한 경우에만** 포함하라. 부정문('교재를 안 가져가요'), 모름 진술('잘 모르겠어요'), 사실과 다른 값('11시에 시작해요'), 다른 대상에 대한 진술('간식을 가져가요')은 found가 아니라 missing으로 처리하라."
- "키워드가 등장했다는 이유만으로 found 처리하지 말 것. 의미가 요소 라벨과 일치해야 한다."
- q3: "들은 내용과 다르게 말한 경우(시간·장소·준비물을 틀리게 재현) task_completion_score를 낮추고 teacher_note에 어떤 정보가 틀렸는지 기록하라."
- evidence에는 "found 판정의 근거가 된 학습자 발화 구절"을 넣고, 부정문이면 그 사실을 teacher_note에 적도록.

### 3-3. mock evaluator — 백업 경로 유지 vs 폐기

**유지 권장(단, 역할 축소).** 근거:
- `evaluateSpeakingDetail()`은 OpenAI 호출 실패 시 절대 throw하지 않고 mock으로 폴백하는 설계 — 운영 안정성상 폴백 경로는 필요.
- 다만 폴백 mock 결과는 **명시적으로 "임시/저신뢰" 표식**(`status: 'fallback'`, `needs_teacher_review: true` 강제, UI 배지)으로 노출해 교수자 확정 전 신뢰하지 않게.
- 폴백 시 mock은 **점수 floor를 적용하지 말고 보수적으로**(현재 q3의 `ratio≥0.33 → 65점` 같은 floor가 오탐과 겹치면 과채점) — 폴백 모드에선 floor 제거하고 키워드 비율 그대로 반영하거나, 아예 "AI 평가 일시 불가, 교수자 검토 필요"로 점수 보류.
- 키워드 테이블(`elementKeywords` 정적 fallback)은 폐기 검토(2-4 참조).
- 테스트/CI·로컬 개발용으로도 mock은 계속 필요(`LLM_EVAL_PROVIDER=mock`).

### 3-4. 기타

- 모델: 현재 기본 `gpt-4o-mini`. q3 같은 의미 판정·부정문 구별은 mini로도 대체로 되지만, 채점 일관성 위해 `temperature: 0.3`(현행) 유지하고 few-shot 예시 1~2개(긍정 found / 부정문 missing / 틀린 값 missing) 추가 권장.
- 비용: 문항당 1콜, max_tokens 1024 — 캐싱 여지는 system prompt(고정) 정도. Anthropic SDK로 가면 prompt caching으로 system+스크립트 블록 캐시 가능.
- 회귀 방지: v1.1 전환 시 mock 경로 단위테스트(현 `scoring-calibration-policy.test.ts` 등)는 그대로 두고, OpenAI 경로는 응답 파싱·클램프·폴백 로직만 단위테스트(LLM 자체는 모킹).
