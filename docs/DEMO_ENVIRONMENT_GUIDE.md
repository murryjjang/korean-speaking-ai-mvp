# 시연 환경 가이드

회원님 직접 작업용 문서. 시연 안전성 확보가 목표. 라이브 4 모드 (q1·q4·발표·생성형 대화) 가운데 어떤 항목이 깨져도 시연이 멈추지 않도록 사전 준비 + 폴백 절차를 정리한다.

---

## A. Chrome 프로필 분리 가이드

학생/교수자/관리자 각각 별도 프로필을 두면 로그인 충돌·쿠키 잔존을 사전에 차단할 수 있다. 시연 4 모드는 학생 프로필에서, 교사 화면 (`/teacher/dashboard`, `/teacher/submissions`)은 교수자 프로필에서, 관리자 분석 (`/admin/analytics`)은 관리자 프로필에서.

### 프로필 만들기

1. Chrome 우상단 프로필 아이콘 클릭 → "다른 프로필 추가".
2. 이름: `시연-학생`, `시연-교수자`, `시연-관리자`. 색상도 구분되게 지정.
3. 각 프로필을 한 번씩 열어 다음을 미리 준비:
   - 해당 역할로 로그인 (브라우저가 비밀번호를 기억하도록 허용)
   - 즐겨찾기 막대에 시연 페이지를 등록 (아래 표 참고)
   - Chrome 왼쪽 상단 + 모양으로 사이트 알림·마이크 권한을 미리 "허용"으로 설정 (`localhost:3000` 기준)

### 즐겨찾기 (각 프로필별)

| 프로필 | 즐겨찾기에 둘 페이지 |
| --- | --- |
| 시연-학생 | `/student/speaking/beginner-q1-reading` (또는 attempt 진입 페이지), `/student/speaking/beginner-q4-dialogue-mission`, `/student/presentation-practice`, `/student/conversation-practice` |
| 시연-교수자 | `/teacher/dashboard`, `/teacher/submissions` |
| 시연-관리자 | `/admin/analytics` |

### 빠른 전환

- 우상단 프로필 아이콘 → 사용할 프로필 클릭. 새 창으로 열림.
- 시연 흐름이 학생→교수자→학생→관리자 순이면 그 순서대로 프로필 창을 미리 띄워 두고 Alt+Tab으로 전환.

### 시크릿 창과의 비교

시크릿 창은 매번 로그인을 다시 해야 하므로 시연용으로는 비효율. 프로필 분리가 더 빠르다. 단, 외부 게스트 PC에서 시연하는 경우엔 시크릿 창 + 매번 로그인이 안전.

## B. 시연 PC 점검 체크리스트

시연 1시간 전 모두 확인. 한 항목이라도 ✗이면 폴백 (사전 녹화) 준비.

### 네트워크

- [ ] 유선 또는 안정적 WiFi (5GHz 권장)
- [ ] `speedtest.net` 다운 30Mbps 이상, 업 10Mbps 이상 확인
- [ ] 핫스팟 백업 (모바일 데이터) 준비
- [ ] LLM API 호출 1회 테스트 (`/student/conversation-practice`에서 1발화 → NPC 응답 도착 확인)

### 음향

- [ ] 외장 마이크 (USB 콘덴서 마이크 권장) — 노트북 내장은 노이즈 많음
- [ ] 노이즈 캔슬링 ON (Krisp, Chrome 내장 noise suppression 등)
- [ ] 스피커 또는 외부 모니터 스피커로 NPC TTS 음성 출력 확인
- [ ] 시스템 마스터 볼륨 70% 이상

### 디스플레이

- [ ] 화면 해상도: 1920x1080 (시연장 프로젝터 호환)
- [ ] 외부 모니터 미러링 (HDMI 케이블 사전 연결 + 어댑터 백업)
- [ ] 듀얼 스크린 사용 시: 메인은 시연용, 보조는 발화 메모용
- [ ] Chrome 줌 레벨 100% (Ctrl+0)

### 브라우저

- [ ] Chrome 최신 버전 (`chrome://settings/help` 확인)
- [ ] 마이크 권한 미리 허용 (`localhost:3000` 사이트 설정에서)
- [ ] 알림 권한 차단 (시연 중 시스템 알림 방지)
- [ ] 확장 프로그램 비활성화 (광고 차단기, ColorZilla 등)
- [ ] DevTools 닫기

### 앱 / 서버

- [ ] dev 서버 실행: `npm run dev` (`http://localhost:3000`)
- [ ] `.env.local` 키 확인 (LLM, Azure, Supabase)
- [ ] `npm run test:unit` 612 그린
- [ ] `npm run lint` 깨끗
- [ ] dev 서버 재기동 후 q1·q4·발표·생성형 대화 1회씩 사전 시연

### 백업

- [ ] q1 / q4 / 발표 / 생성형 대화 사전 녹화 영상 (스크린 + 음성)
- [ ] 시연 멘트 인쇄본 (`docs/DEMO_SCRIPT.md` 출력)
- [ ] 노트북 충전기 + 보조 배터리

## C. 폴백 결정 트리

문제 발생 시 즉시 따라갈 흐름. 머뭇거리지 않는 게 핵심.

### 문제 1: LLM 호출 실패 (q4 / 발표 / 생성형 대화 NPC 응답 실패)

- **증상**: 응답이 5초 이상 도착 안 함, 또는 에러 토스트.
- **자동 폴백**: 코드에 mock 응답이 박혀 있어 자동 전환 (`source: 'mock'` 배지가 표시됨).
- **시연 멘트**: "지금 네트워크가 잠시 불안정해서 기본 응답으로 데모를 이어 가겠습니다. 실제 환경에서는 LLM 응답이 매번 자연스럽게 달라집니다."
- **수동 대처**: 그래도 안 되면 사전 녹화 영상으로 전환.

### 문제 2: Azure 발음 평가 실패 (q1 / 읽기 / 발표 발음 점수)

- **증상**: 점수 영역에 "참고평가" 문구 + provider=`demo` 배지.
- **자동 폴백**: demo 평가 결과가 자동 표시.
- **시연 멘트**: "정밀 발음평가 v2는 안정화 단계라 오늘은 참고 평가 화면으로 보여드립니다."
- **수동 대처**: 별도 행동 불필요. 시연 흐름 그대로 진행.

### 문제 3: 인터넷 끊김 (모든 API 실패)

- **증상**: 모든 모드에서 응답이 안 옴 + dev 서버 콘솔에 fetch 에러.
- **자동 폴백**: 핫스팟으로 전환 시도 (1분 이내).
- **수동 대처**: 1분 내 복구 안 되면 사전 녹화 영상으로 전환.
- **시연 멘트**: "시연 환경 네트워크 이슈가 있어 사전 녹화 영상으로 보여드리겠습니다. 실제 사용 흐름은 그대로 보존되어 있습니다."

### 문제 4: 마이크 인식 안 됨

- **증상**: 녹음 시작 후 0초로 멈춤, 또는 STT 결과가 빈 문자열.
- **즉시 대처 (생성형 대화)**: 텍스트 입력으로 전환 — textarea에 직접 타이핑 후 Enter.
- **즉시 대처 (q1 / 발표)**: 사전 녹음 음성 파일로 전환, 또는 녹음 시연을 건너뛰고 결과 화면 직접 시연.
- **시연 멘트**: "마이크 환경 점검을 위해 텍스트 입력으로 전환하겠습니다."

### 문제 5: TTS 음성 안 나옴 (생성형 대화 NPC 음성)

- **증상**: NPC 응답 텍스트는 보이지만 스피커에서 소리 안 남.
- **자동 폴백**: 텍스트는 정상 표시되므로 시연 흐름은 끊기지 않음.
- **수동 대처**: 헤더 토글 "NPC 음성 자동 재생" 다시 ON/OFF 한 번씩, 또는 메시지 옆 🔊 버튼 클릭.
- **시연 멘트**: 이슈를 굳이 언급하지 말 것. 자연스럽게 진행.

### 문제 6: 페이지가 404 / 변경 반영 안 됨

- **증상**: 코드 수정한 게 시연 페이지에 안 보임, 또는 갑자기 404.
- **원인**: `.next` 빌드 캐시 stale (CLAUDE.md 트러블슈팅 참고).
- **대처**: dev 서버 종료 → `rm -rf .next` → `npm run dev`. 1분 가량 소요.
- **시연 멘트**: 시연 시작 전 발견되도록 1시간 전 점검에 포함.

## D. 리허설 시나리오

시연 전 최소 2~3회 리허설. 각 회 후 발견 이슈 즉시 보정.

### 시간표 (총 10분)

| 구간 | 시간 | 내용 | 모드 |
| --- | --- | --- | --- |
| 0:00 ~ 3:00 | 3분 | 슬라이드 도입 + 6 모드 소개 (q1~q4 + 읽기 + 발표) | 슬라이드 |
| 3:00 ~ 5:00 | 2분 | q4 대화 미션 라이브 (카페 주문) | 라이브 |
| 5:00 ~ 6:30 | 1.5분 | 발표 연습 라이브 (한국의 겨울 날씨) | 라이브 |
| 6:30 ~ 8:30 | 2분 | 생성형 대화 라이브 (주말 명소) | 라이브 |
| 8:30 ~ 9:00 | 0.5분 | 슬라이드 (생성형 쌍방 교재 v2 비전) | 슬라이드 |
| 9:00 ~ 10:00 | 1분 | 마무리 + Q&A | 발화 |

### 라이브 발화 시퀀스

`docs/DEMO_SCRIPT.md` 의 q4 / 발표 / 생성형 대화 섹션을 그대로 사용. 인쇄본을 대본으로 참고.

### 멈춤 / 전환 신호

- 슬라이드 → 라이브 전환 시: "그럼 실제 화면을 보시겠습니다."
- 라이브 → 라이브 전환 시: 다음 모드 즐겨찾기 클릭 (Chrome 시연-학생 프로필)
- 라이브 → 슬라이드 전환 시: "보신 것처럼 ..." (요약 한 문장)

### 리허설 후 체크리스트

- [ ] 각 모드 시연 시간이 표대로 들어가는가
- [ ] 마이크 / 스피커 / 화면 해상도 모두 정상
- [ ] 폴백 트리거 1회 이상 시뮬레이션 (예: WiFi 일시 차단 → 핫스팟 전환 시간 측정)
- [ ] 슬라이드 ↔ 브라우저 전환 매끄러운가 (Alt+Tab 또는 듀얼 스크린)
- [ ] 발화 호흡이 시간 안에 들어가는가 (특히 발표 1분 분량 원고)
