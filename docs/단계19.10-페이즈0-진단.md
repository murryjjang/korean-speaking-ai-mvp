### #3. PDF 피드백 불릿 한국어/보조 줄바꿈 누락

**원인 가설**: `BilingualListItem`(src/components/ui/bilingual-text.tsx:133-150)에서 supplement span에 `block` 클래스 적용했으나 PDF 렌더 시 실제로 줄바꿈이 안 됨.

**관련 파일**:
- `src/components/ui/bilingual-text.tsx:138-148` — `<li>` 안 `<span lang="ko">{ko}</span>` 다음 `<span className="block text-[11px]...">{supplement}</span>`
- 호출처: `app/student/conversation-practice/free-conversation-client.tsx:1378-1421` — 잘한 점/다음 연습 시 두 ul 모두 `list-disc list-inside`
- PDF 라우트: `app/api/pdf/route.ts` + `src/components/pdf-download-button.tsx`(self-contained HTML → Puppeteer)
- PDF print CSS: `pdf-download-button.tsx:66-83` — `button { display: none }`만 있고 list 관련 reset 없음

**실제 코드 상태**:
- 부모 `<ul>`이 `list-disc list-inside`. 첫 `<span lang="ko">`는 inline. `block` 클래스 보조 span은 이론상 줄바꿈 되어야 하나, 사용자 보고에 의하면 PDF에서 같은 줄에 붙어 출력됨.
- 가설: 부모 `<ul>`의 `list-disc list-inside`가 li 콘텐츠를 inline-flow처럼 다루며, 보조 span의 `display:block`이 일부 Tailwind 빌드 변환 또는 puppeteer print CSS와 충돌 가능. 또는 `mt-0.5`만으로는 시각적 분리가 부족해 같은 줄로 보임.

**픽스 범위**:
- 파일 수: 1개 (`src/components/ui/bilingual-text.tsx`)
- 작업: BilingualListItem 구조를 div-block 기반으로 강제 + visual 간격(`mt-1` + 명시적 leading) + 인라인 style `display:block`로 안전망
- 작업 시간: **10~15분**
- 위험도: 낮음 (이미 unit test 있음, 회귀 가능성 낮음)
